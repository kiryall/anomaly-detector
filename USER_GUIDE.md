# Anomaly Detector — инструкция пользователя

## 1. Запуск программы

### Из исходного кода (разработка)

1. Откройте папку `anomaly-detector`
2. Убедитесь, что установлен `uv` ([установка](https://docs.astral.sh/uv/getting-started/installation/))
3. Выполните установку зависимостей (первый раз):
   ```powershell
   cd app
   uv sync
   cd ..
   ```
4. Запустите файл `run.bat` двойным кликом
5. Подождите открытия браузера с интерфейсом приложения (порт 8080)

### Собранный EXE

1. Откройте папку `release\AnomalyDetector`
2. Запустите `AnomalyDetector.exe`
3. Подождите открытия браузера с интерфейсом приложения (порт 8080)

## 2. Выбор модели

1. Убедитесь, что ONNX-модель (.onnx файл) находится в папке `models/`:

   ```
   anomaly-detector/
   └── models/
       ├── best.onnx
       └── best.json    # Имена классов (автоматически)
   ```

2. В интерфейсе приложения в выпадающем списке **«Модель»** выберите нужную модель
3. Если модель не отображается — перезапустите приложение

## 3. Выбор папки с фотографиями

1. Нажмите кнопку **«Выбрать»** рядом с полем «Папка»
2. В открывшемся диалоге выберите каталог с фотографиями для обработки
3. Приложение покажет количество найденных изображений

> **Поддерживаемые форматы:** `.jpg`, `.jpeg`, `.png`, `.bmp`, `.tif`, `.tiff`, `.webp`

## 4. Confidence (Порог уверенности)

1. Установите значение порога уверенности в поле **«Порог уверенности»**
2. Диапазон: от 0.00 до 1.00
3. Рекомендуемое значение: **0.25–0.80**
4. Чем выше значение — тем строже критерий обнаружения дефектов

> Настройка автоматически сохраняется между запусками.

## 5. Запуск детекции

1. Убедитесь, что выбрана **модель** и **папка** с изображениями
2. Нажмите кнопку **«Начать детекцию»**
3. Статус изменится на «Идёт детекция...»
4. После завершения появится сообщение с результатами

## 6. Результаты

Результаты детекции сохраняются в папке `data/output/`:

```
data/output/
└── output_<имя_модели>/
    ├── crater/       # Изображения с дефектом «Crater»
    ├── noize/        # Изображения с дефектом «Noize»
    └── no_defect/    # Изображения без дефектов
```

Каждое изображение сохраняется в каталоге, соответствующем обнаруженному классу дефекта.

## 7. Несколько дефектов на одном изображении

Если на изображении обнаружено несколько типов дефектов, оно будет сохранено в **каждой соответствующей папке**:

```
image_001.jpg
├── crater/  ← сохранено здесь (Crater, confidence=0.91)
└── noize/   ← сохранено здесь (Noize, confidence=0.83)
```

Если ни один дефект не прошёл порог confidence — изображение попадёт в `no_defect/`.

## 8. Изображения с bounding boxes

Все изображения, сохранённые в папках результатов, содержат **отрисованные bounding boxes** — рамки вокруг обнаруженных дефектов с подписями класса и уверенности.

Изображения без дефектов сохраняются в исходном виде (без изменений).

## 9. Excel-отчёт

1. После завершения детекции активируется кнопка **«Сохранить отчёт»**
2. Нажмите её для сохранения Excel-файла
3. Отчёт содержит два листа:
   - **Сводка** — общая статистика обработки
   - **Детекции** — детальная информация по каждому изображению

### Содержание отчёта

**Лист «Сводка»:**

| Поле | Описание |
|------|----------|
| Модель | Имя использованной модели |
| Папка | Источник изображений |
| Порог уверенности | Значение confidence threshold |
| Всего изображений | Количество обработанных файлов |
| Обнаружено аномалий | Изображений с дефектами |
| Без дефектов | Изображений без дефектов |
| Всего дефектов | Суммарное число обнаруженных дефектов |
| Multi-class | Изображений с несколькими дефектами |
| Ошибки | Количество ошибок обработки |
| Время инференса | Общее и среднее время на изображение |

**Лист «Детекции»:**

| Поле | Описание |
|------|----------|
| Изображение | Имя файла |
| Путь | Полный путь к исходному файлу |
| Класс | Имя обнаруженного дефекта |
| Class ID | Идентификатор класса |
| Confidence | Уверенность обнаружения |
| Bounding Box | Координаты рамки (x1, y1, x2, y2) |
| Выходная папка | Каталог сохранения |
| Выходной путь | Полный путь к сохранённому файлу |
| Время инференса | Время обработки изображения |

## 10. Где найти отчёт

Excel-отчёты сохраняются в папку:

```
data/reports/
```

Имя файла: `report_YYYYMMDD_HHMMSS.xlsx`

## 11. Добавление новой модели

1. Скопируйте `.onnx` файл модели в папку `models/`:

   ```
   anomaly-detector/
   └── models/
       ├── best.onnx
       └── new_model.onnx    ← новая модель
   ```

2. Перезапустите приложение
3. Новая модель появится в выпадающем списке выбора модели

## 12. Конфигурация

Настройки хранятся в файле `config/settings.json`:

| Параметр | Тип | По умолчанию | Описание |
|----------|-----|:---:|----------|
| `model` | string | `""` | Имя выбранной модели |
| `confidence` | float | `0.40` | Порог уверенности (0.0–1.0) |
| `iou` | float | `0.50` | Порог IoU для NMS (0.0–1.0) |
| `copy_images` | bool | `true` | Копировать изображения в output |
| `save_database` | bool | `true` | Сохранять базу данных |
| `last_folder` | string | `""` | Последняя выбранная папка |
| `theme` | string | `"dark"` | Тема UI |

Изменения вступают в силу после перезапуска приложения.

## 13. Завершение работы

1. Нажмите кнопку **«Завершить работу»** внизу интерфейса
2. Подтвердите действие в диалоговом окне
3. Закройте вкладку браузера

> Нельзя завершить программу во время обработки изображений. Дождитесь завершения детекции.

## 14. Возможные ошибки

### «Выберите модель»
— Не выбрана модель. Выберите модель из списка.

### «Выберите папку с фотографиями»
— Не выбрана папка для обработки. Нажмите «Выбрать» и укажите каталог.

### «В выбранной папке нет изображений»
— Указанная папка пуста или не содержит поддерживаемых форматов изображений.

### «Выбранная модель не найдена»
— Файл модели был удалён или перемещён. Поместите `.onnx` файл обратно в `models/`.

### «Ошибка: ...»
— Проверьте, что путь к модели и папке корректны, и у вас достаточно ресурсов системы.

### Приложение не запускается
— Убедитесь, что установлен `uv` и зависимости: `cd app && uv sync`

### Ошибка «source code string cannot contain null bytes»
— Это известная проблема NiceGUI при запуске из собранного EXE. Убедитесь, что используется актуальная версия приложения. Если ошибка возникает — пересоберите проект через `build.bat`.
